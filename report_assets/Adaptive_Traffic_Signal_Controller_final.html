02 · Introduction

Introduction & objectives

  • Fixed-time signals repeat a preset cycle, whatever is queued.
  • An IoT pipeline links sensing, messaging, storage, control and actuator feedback.
Problem statement

Can an IoT-based controller read the traffic state, pick a bounded green time, apply it through an actuator and check the acknowledgement — and do better than fixed timing?

Objectives
1IoT pipeline: simulation → messaging → storage → analytics → decision → actuation
2Prepare a dataset: readings, signal cycles, adaptive decisions
3Deterministic adaptive controller and a fixed-time baseline
4Compare Logistic Regression, Random Forest, Gradient Boosting, MLP
5Measure fit time, latency, memory and model size
6Evaluate closed-loop queues, ACKs and signal safety
7Dashboard and testing tools

MQTT communication

How it works
  • Publish–subscribe messaging protocol
  • A publisher sends to a topic; the broker forwards it to subscribers
  • Producers and consumers stay decoupled
  • JSON messages with timestamps or IDs
  • QoS levels trade delivery guarantees against overhead

12 · Gradient Boosting

Gradient Boosting: algorithm

Idea
  • Sequential ensemble of decision trees
  • Each new tree is trained to reduce the errors left by the trees before it
  • Tree outputs are added together, scaled by the learning rate
  • Shallow trees keep each learner simple
Sequential building
Tree 1→Tree 2→· · ·→Tree 150

Each tree focuses on what the earlier trees got wrong.

Sum of trees → Low / Medium / High

Testing, safety & conclusion

Closed-loop testing · fixed-time vs adaptive
MeasureAvg delayAvg queueMax queueJain fairnessMax red wait
Fixed-time139.4 s7.0051130.95795 s
Adaptive76.6 s3.848210.992164 s

Simulation: shorter delay, longer worst-case red wait.

Safety / fallback
  • 37/37 phase ACKs accepted; no violations on successful paths
  • 4/4 RED ACKs confirm Stop/Reset
  • One ACK withheld → unconfirmed, restart inhibited
  • 200 automated tests passed, 0 failed
Docker deployment verification
  • Containers started successfully
  • MQTT communication verified
  • Node-RED dashboard accessible
  • Persistent volumes configured
  • WebSocket traffic verified
Docker security
  • Node-RED editor not publicly exposed
  • MQTT port not publicly exposed
  • SQLite kept internal
  • Authenticated dashboard access
  • Only required services exposed
Conclusion. The system provides adaptive signal control in simulation using IoT, MQTT, Node-RED and SQLite, with offline ML analytics. Delay and queues fell; every safe-state command is verified by acknowledgement. Dockerization improved deployment consistency by packaging the application, MQTT broker, and Node-RED environment into reproducible containers.
